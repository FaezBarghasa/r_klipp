# Agent Rules & Testing Standards for `r_klipp`

This document defines mandatory validation rules, verification contracts, and testing procedures for AI agents and developers working across the **`r_klipp`** codebase.

---

## 🛠️ Foundational Testing Tools (`./tools/`)

The repository provides automated test tools in `./tools/` for verifying bare-metal Embedded Rust and containerized Linux UI components.

---

### 1. Embedded QEMU Test Runner (`./tools/run_qemu_test.sh`)

`./tools/run_qemu_test.sh` automates compiling and executing ARM Cortex-M embedded firmware binaries within the QEMU system emulator (`lm3s6965evb` machine model).

#### **Contract & Behavior**
- **Target**: Builds for the `thumbv7em-none-eabihf` target in release mode.
- **QEMU Parameters**:
  ```bash
  qemu-system-arm \
    -machine lm3s6965evb \
    -cpu cortex-m3 \
    -nographic \
    -serial mon:stdio \
    -kernel <path_to_kernel_elf>
  ```
- **Log Capture**: Captures the complete serial output stream and prints it to stdout.
- **Exit Code Contract**: Returns exit code `0` **ONLY** if the serial log output contains the exact token:
  ```
  TESTS PASSED
  ```
  If this token is missing or if the process times out/crashes, it terminates with a non-zero exit code (`1`).

#### **Usage**
```bash
# Run with default binary target (target/thumbv7em-none-eabihf/release/your_app)
./tools/run_qemu_test.sh

# Run with a specific crate / binary name
./tools/run_qemu_test.sh klipper-mcu-firmware

# Run with a specific binary path
./tools/run_qemu_test.sh target/thumbv7em-none-eabihf/release/my_test_bin

# Override default timeout (in seconds)
QEMU_TIMEOUT=30 ./tools/run_qemu_test.sh klipper-mcu-firmware
```

### 2. Slint UI Docker Test Runner (`./tools/test_slint_docker.sh`)

`./tools/test_slint_docker.sh` executes the Embedded Linux + Slint touch operator interface inside an isolated Docker container with software-accelerated OpenGL and headless display virtual framebuffers.

#### **Contract & Behavior**
- **Docker Compose Orchestration**: Executes `docker compose up --build` (or `docker-compose up --build`).
- **Headless Display & GPU Environment**:
  - `xvfb-run` creates a virtual X11 server buffer (`DISPLAY=:99`).
  - `LIBGL_ALWAYS_SOFTWARE=1` forces Mesa software OpenGL rasterization.
  - `SLINT_BACKEND=software` or GL renderer fallback.
- **Healthcheck & Exit Verification**: Polls container health state until healthy or finished.
- **Failure & Panic Scanning**: Scans container logs for:
  - `panicked at`
  - `fatal runtime error`
  - `Slint rendering error`
  - `UI test failure`
  - `failed to initialize rendering backend`
  - `SIGSEGV` / `core dumped`
- **Exit Code Contract**: Returns exit code `0` on healthy execution without panics or failures; returns `1` otherwise. Cleans up all Docker containers automatically upon exit.

#### **Usage**
```bash
# Execute containerized Slint UI tests
./tools/test_slint_docker.sh

# Customize container wait timeout (in seconds)
DOCKER_WAIT_TIMEOUT=120 ./tools/test_slint_docker.sh
```

## 📋 Agent Guidelines & Pre-Verification Checklist

Before declaring any feature or bug fix complete:

1. **Embedded Firmware Changes** (`crates/klipper-mcu-firmware`, `crates/mcu-drivers`, `crates/hal`):
   - Run `cargo lint-mcu` (`clippy` on `thumbv7em-none-eabihf`).
   - Run `./tools/run_qemu_test.sh` to ensure target buildability and QEMU serial verification.

2. **Host UI Changes** (`host-ui`):
   - Verify Slint definitions compile cleanly (`cargo check -p host-ui`).
   - Run `./tools/test_slint_docker.sh` to verify headless rendering and container health under `xvfb-run`.

3. **Core Motion & Protocol Changes**:
   - Run `cargo test-core` to verify deterministic trajectory calculations and protocol framing.
