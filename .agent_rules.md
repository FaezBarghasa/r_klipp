## 🛠️ Hardware Simulation & Testing Tools (`./tools/`)

### 1. Embedded MCU QEMU Test Runner (`./tools/run_qemu_test.sh`)

Simulates the bare-metal MKS SKIPR microcontroller in QEMU ARM Cortex-M emulation.

#### **Execution & Parameters**
- **Target**: `thumbv7em-none-eabihf` (Release mode).
- **QEMU Machine**: `-machine lm3s6965evb -cpu cortex-m3 -nographic -serial mon:stdio`.
- **Exit Code Contract**: Returns exit code `0` **ONLY** if the serial log output contains the exact token:
  ```
  TESTS PASSED
  ```
  If this token is missing or the simulation times out, the command exits with code `1`.

#### **Usage**
```bash
# Build and run default MCU firmware under QEMU
./tools/run_qemu_test.sh klipper-mcu-firmware

# Run with custom timeout (seconds)
QEMU_TIMEOUT=30 ./tools/run_qemu_test.sh klipper-mcu-firmware
```

---

### 2. Full-Stack Docker & KVM Test Runner (`./tools/test_slint_docker.sh`)

Simulates the MKS SKIPR Embedded Linux Host stack (`host-server` backend + `host-ui` Slint frontend for MKS PI_TS35 display) inside Docker Compose with optional KVM acceleration.

#### **Execution & Environment**
- **Backend Validation**: Tests Actix-Web Moonraker endpoints (`/printer/info`, `/printer/objects/query`, `/printer/gcode/script`, `/server/info`, `/server/files/list`) and WebSocket telemetry streaming.
- **Frontend Validation**: Tests Slint UI operator interface running in virtual X11 buffer (`xvfb-run -s "-screen 0 480x320x24"`) matching the MKS PI_TS35 3.5" panel resolution with `LIBGL_ALWAYS_SOFTWARE=1` and `SLINT_BACKEND=software`.
- **Log Inspection**: Scans container logs for panics (`panicked at`), rendering crashes, or UI test failures.
- **Exit Code Contract**: Returns exit code `0` on healthy execution without panics or test failures; returns `1` otherwise.

#### **Usage**
```bash
# Run Docker Compose Slint + Host full-stack test
./tools/test_slint_docker.sh

# Run with custom wait timeout
DOCKER_WAIT_TIMEOUT=120 ./tools/test_slint_docker.sh
```

---

### 3. Unified End-to-End Simulation Runner (`./tools/run_fullstack_hardware_sim.sh`)

Executes the complete two-phase hardware verification pipeline (MCU in QEMU + Host & Slint TS35 in Docker/KVM):

```bash
./tools/run_fullstack_hardware_sim.sh
```

## 📋 Agent Pre-Verification Checklist

Before concluding any work on embedded firmware or host components:

1. **Embedded Rust Changes** (`crates/klipper-mcu-firmware`, `crates/mcu-drivers`, `crates/hal`):
   - Run `cargo lint-mcu` (`clippy` on `thumbv7em-none-eabihf`).
   - Run `./tools/run_qemu_test.sh klipper-mcu-firmware` to verify bare-metal execution in QEMU.

2. **Host Server & Slint UI Changes** (`host-server`, `host-ui`):
   - Run `cargo test -p host-server` to test REST API and SurrealDB models.
   - Run `LD_LIBRARY_PATH="$(pwd)/target/pkgconfig" LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a cargo test -p host-ui` to test Slint window lifecycle and touch callbacks.
   - Run `./tools/test_slint_docker.sh` to test the containerized full stack simulating MKS PI_TS35 hardware.

3. **Motion Planner & Core Logic Changes**:
   - Run `cargo test-core` to verify deterministic trajectory calculations and protocol framing.
